# ADR 0005 · Independent review provenance

Accepted for implementation. Review eligibility and identity are checked against policy. Persist the reviewed commit, reviewer identity and execution provenance. Missing evidence cannot satisfy a required independent review. Enforcement for execution reviews belongs to a later package.

The controller can accept an independent review after a local or remote build finishes and releases its lease. Configure `FACTORY_REVIEW_PUBLIC_KEY` on the controller with the external review authority's PEM public key. Keep the corresponding private key outside the controller, builders and workers. Before signing a PASS, the authority must authenticate the reviewer, establish read-only separation from the builder and independently verify the configured checks on the exact commit that will be published. For a remote build, use the archived build commit and authenticate the builder session outside the worker's report. Worker check and session claims alone do not establish quality or independence.

Send the signed decision to the authenticated administrator endpoint `POST /api/review-approvals`. Sign the UTF-8 bytes of `Json.Stringify(ReviewApproval)` with RSA-PSS and SHA-256, then Base64-encode the signature. The decision identifies the project, job, execution generation, latest completed cycle, commit, policy and project contract revisions, reviewer and builder identities and sessions, and expiry. `GET /api/jobs/{id}/review-approved` reports current eligibility. Consult it for a manual PR handoff and pin the PR to the reviewed commit. Required GitHub CI still runs against the PR.

Remote completion closes the controller's reserved review cycle in the completion transaction. A matching completed build enters `await_signed_remote_review`, with bounded worker evidence recorded as UNKNOWN. The approval is pinned to the archived commit, with the origin and base branch included in the review project revision captured at check time. The publisher must use the exact approved object ID during handoff, including if the worker's branch subsequently moves.

After the approved pull request merges, call `POST /api/jobs/{id}/verify?pullRequestUrl=<URL-encoded GitHub PR URL>`. The controller requires the expected repository and job branch, approved head, configured base branch, successful required GitHub checks, and a complete permitted PR file list. It verifies the merge commit in the remote base and records the PR evidence and integration together, after rechecking the signed approval.

The signed approval requirement applies to every new remote integration confirmation. Legacy `PrReady` rows without a signed review cannot be confirmed through the integration endpoint. Use a fresh authorized build and review to obtain current evidence.

The controller counts admitted cycles throughout the lifetime of the job, including rounds interrupted by lease loss. Reconciliation and resume preserve that count. Exhaustion leaves a blocked handover with the existing review evidence. A new contract requires separate authorization.

Execution failures record a typed disposition and the durable checkpoint. Timeouts away from Git mutations require an explicit retry. Policy failures require the relevant budget or scope decision. Worktree conflicts require reconciliation. Uncertain commit, push, PR or merge operations stay blocked for operator reconciliation. Inspect both the local checkpoint and authoritative GitHub state before authorizing any replacement work.
