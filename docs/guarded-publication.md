# Guarded publication

`POST /api/jobs/{id}/publication` is an administrator operation. It requires a separate signed project decision. Configure the integration authority public key in `FACTORY_INTEGRATION_PUBLIC_KEY`. The authority signs the UTF-8 bytes of `Json.Stringify(PullRequestDecision)` using RSA-PSS and SHA-256. The approval limits the operation to the exact job, project revision, repository, base branch and commit, head, scope, GitHub account, method and expiry.

Publication requires AllowPush and an eligible signed review. A decision with action draft, method pr-ci and pull number zero authorizes a draft for PR-triggered CI. Merge also requires AutoMerge, which defaults to false. A merge decision names the PR and selected merge method. The PR must already be out of draft and have independent GitHub approval and successful required checks on its exact head.

A durable reservation precedes each mutation. After an uncertain operation, inspect GitHub and the audit records. The coordinator will not resend a reserved mutation. If GitHub reports a matching merge, submit the signed decision again to verify the merge and persist integration.
The draft endpoint operates on a pre-published Factory branch. Branch-check availability is an explicit signed decision from the integration authority. When branch CI is available, the controller verifies required check runs and their configured GitHub apps before creating the draft. Merge requires a non-admin credential and visible strict repository rules with no bypass actors. A clean local base is fast-forwarded before confirming integration.
GitHub does not offer an atomic expected-base condition for PR merge. The coordinator checks merge eligibility and refuses the write on GitHub. An operator can submit a signed decision for an already merged PR for verification. Ordinary merges must match both signed parents, and supported squash and rebase history must have the reviewed tree and signed base. Draft creation requires a server-locked branch that cannot be updated or deleted under the visible rules. PR-only CI requires a required context pinned to the GitHub Actions app.

When GitHub omits a workflow run's pull request metadata, the integration request must carry a signed workflow event receipt. Configure FACTORY_WORKFLOW_EVENT_PUBLIC_KEY with a separate authority's PEM public key. That authority must independently authenticate the original GitHub pull request event and its attribution to the actual workflow attempt. It must bind repository, workflow ID, run ID, attempt, check suite ID, PR number, base branch, base SHA and head SHA. Sign the UTF-8 bytes of Json.Stringify(WorkflowEvent) with RSA-PSS SHA-256 and send the Base64 signature in EventProof. The authority must derive this receipt from authenticated attempt-specific evidence. A required check designation or a caller-provided PR number is insufficient. The controller also requires the exact check node issued by that attempt to match the repository-required check.
Subscribe GitHub repository webhooks to workflow_run events at POST /api/github/workflow-events on a reachable HTTPS controller. Configure FACTORY_GITHUB_WEBHOOK_SECRET to the same value on both ends, and configure the issuer private and verification public keys. This route authenticates raw deliveries using X-Hub-Signature-256 and stores the exact signed receipt for registered repository/base pairs. Duplicate deliveries are idempotent. The issuer still requires a webhook containing one authoritative PR association. A delivery with no association fails closed.
